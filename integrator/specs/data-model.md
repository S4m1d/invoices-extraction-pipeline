# Integrator: Data Model (PostgreSQL)

Simple procurement layout; nothing elaborate such as a purchase order id. Field set follows `fields-extractor/specs/extraction-schema.md` (ADR 0008).

## Tables

- `invoices`
- `invoice_lines`

Relation: one `invoices` row has many `invoice_lines` rows.

## `invoice_lines`

| Column | Type | Null | Notes |
|---|---|---|---|
| `id` | uuid, PK | no | |
| `invoice_id` | uuid, FK -> `invoices.id` | no | `on delete cascade` |
| `line_no` | int | no | Unique per invoice; check `line_no >= 1` |
| `description` | text | no | |
| `quantity` | numeric | yes | |
| `unit_price` | numeric | yes | |
| `amount` | numeric | no | |

An invoice and all its lines are inserted in one transaction.

## Numeric columns

All money, quantity and rate columns are unconstrained `numeric`: values are stored exactly as extracted (decimal strings in `extracted.json`), with no rounding and no precision limit. In run-001 the largest values have 6 integer digits, `unit_price` up to 4 decimals and amounts 2; a fixed `numeric(p,s)` would either round (losing the printed value) or reject unusual invoices. Negative values are allowed (credits).

## Constraints and indexes

- `invoices`: primary key `id`; unique `document_id` (also the tester's lookup key); check on `currency`.
- `invoice_lines`: primary key `id`; unique `(invoice_id, line_no)` (also serves lookups by invoice); foreign key `invoice_id` with `on delete cascade`; check `line_no >= 1`.
- No further indexes for the MVP: the tester reads by `document_id`. Indexes for other queries are added when such queries exist.

## Access

- The integrator connects as role `integrator` (owner of the schema, applies migrations).
- The tester reads with a separate read-only role `tester` (`SELECT` on both tables). Roles and grants are created by `infra/`.
